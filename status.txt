1. PROJECT PURPOSE, MISSION & CORE SECURITY MODEL
================================================================================
Covert Chatter (Whisper Drop) is a zero-knowledge, ultra-private, ephemeral
WebRTC communication platform designed for direct peer-to-peer (P2P) messaging
and secure data exchange without any intermediary server storage.

Foundational Security & Cryptographic Principles:
1. Zero Knowledge:
   - Central servers NEVER receive, inspect, log, or persist any message text,
     encryption keys, files, or user metadata.
2. Hardware & Sandboxed Keystore Isolation (Pass 1):
   - Cryptographic keypairs (ECDSA P-256 for signing, ECDH P-256 for key agreement)
     are generated with `extractable: false`.
   - Private key bytes remain locked inside the browser's cryptographic module
     and cannot be extracted via JavaScript or malicious XSS scripts.
3. Direct Peer-to-Peer Data Channels (Pass 2):
   - All communications flow directly between browser instances over WebRTC
     `RTCDataChannel` ("chat") negotiated via STUN (`stun:stun.l.google.com:19302`).
4. Authenticated End-to-End Encryption - E2EE (Pass 3):
   - Ephemeral AES-256-GCM symmetric session keys derived via ECDH Diffie-Hellman.
   - Fresh, cryptographically secure 12-byte (96-bit) IVs generated for every single message.
   - Every message ciphertext is digitally signed with the sender's non-extractable ECDSA private key.
   - Recipients cryptographically verify signatures before attempting decryption (silent drop on tamper).
5. True Ephemeral Message Lifecycle & Anti-Persistence (Pass 4):
   - Expiry timestamps and burn parameters are cryptographically signed inside the inner payload.
   - Default TTL: 60 seconds ticking down in real time.
   - Burn-on-Read: 5-second self-destruct countdown initiated upon recipient render.
   - Zero Persistence Invariant: Messages are held ONLY in transient React state (volatile RAM).
     Never written to localStorage, sessionStorage, or IndexedDB.
   - Memory is immediately purged on room exit, tab close, or 30-second background blur.

[A] BACKEND SIGNALING SERVER (server/)
--------------------------------------------------------------------------------

* Package Config: package.json (whisper-drop-server v1.0.0, dependency: ws@^8.18.0)
* Documentation: README.md

Key Architecture in server.js:
1. `rooms`: Map<roomCode, Set<WebSocket>> (holds room peer socket sets in memory).
2. `clientRooms`: Map<WebSocket, roomCode> (maps client socket to active room code).
3. `generateRoomCode()`: Uses `crypto.randomBytes(3).toString('hex').toUpperCase()` to create unique 6-character room codes.
4. `leaveAndDestroyRoom(ws)`: Immediately closes remaining peer socket with {"type": "peer-disconnected"}, deletes room from memory, and triggers garbage collection.
5. Signaling Event Routing:
   - "create": Registers host, assigns room code, replies with {"type": "created", "room": code}.
   - "join": Validates room existence and capacity (max 2 peers), replies with {"type": "joined", "room": code}, and notifies host with {"type": "ready"}.
   - "offer", "answer", "candidate": Transparently forwards payload to the other peer without logging.
   - "close" / "error": Automatically executes room destruction.

--------------------------------------------------------------------------------
* Location: e:\Covert Chat\client\src\utils\crypto.js

Key Cryptographic Functions:
1. `generateSigningKeypair()`: Generates ECDSA NIST P-256 keypair with `extractable: false` for digital signatures.
2. `generateAgreementKeypair()`: Generates ECDH NIST P-256 keypair with `extractable: false` for key agreement.

5. `deriveSharedSecret(myEcdhPrivateKey, peerEcdhPublicKeyJWK)`: Computes shared curve point via ECDH Diffie-Hellman and derives a 256-bit AES-GCM CryptoKey (`extractable: false`).
6. `validatePeerIdentityPayload()`: Verifies QR/JSON identity structure and curves.

[C] MESSAGE ENCRYPTION & SIGNING SUBSYSTEM (client/src/utils/encryption.js)
--------------------------------------------------------------------------------
* Location: e:\Covert Chat\client\src\utils\encryption.js

Key Functions:
1. `encryptMessage(sessionKey, plaintext)`:
   - Generates a fresh random 12-byte (96-bit) IV for every message (preventing AES-GCM nonce-reuse attacks).
   - Encrypts plaintext via AES-GCM with a 128-bit authentication tag.
2. `decryptMessage(sessionKey, iv, ciphertext)`: Authenticates and decrypts ciphertext into UTF-8 plaintext.
3. `signMessage(myEcdsaPrivateKey, ciphertext)`: Digitally signs ciphertext bytes using ECDSA SHA-256.
4. `verifyMessage(peerEcdsaPublicKeyJWK, ciphertext, signature)`: Validates sender's signature before decryption. Silently drops invalid messages without leaking information.

5. WEBSOCKET SIGNALING PROTOCOL SPECIFICATION MATRIX
================================================================================
| Direction       | Message Type        | Payload Structure                                               | Action / State Transition                                      |
|-----------------|---------------------|-----------------------------------------------------------------|----------------------------------------------------------------|
| Client -> Server| `create`            | `{"type": "create"}`                                            | Requests new 6-char room code                                  |
| Server -> Client| `created`           | `{"type": "created", "room": "XXXXXX"}`                         | Returns room code; sets host to "Waiting for peer"             |
| Client -> Server| `join`              | `{"type": "join", "room": "XXXXXX"}`                            | Joiner requests to enter room                                  |
| Server -> Client| `joined`            | `{"type": "joined", "room": "XXXXXX"}`                          | Joiner confirmed in room                                       |
| Server -> Host  | `ready`             | `{"type": "ready"}`                                             | Signals host to create DataChannel & generate SDP offer        |
| Peer <-> Peer   | `offer`             | `{"type": "offer", "sdp": ...}`                                 | Relays SDP offer to joiner                                     |
| Peer <-> Peer   | `answer`            | `{"type": "answer", "sdp": ...}`                                | Relays SDP answer to host                                      |
| Peer <-> Peer   | `candidate`         | `{"type": "candidate", "candidate": ...}`                       | Relays ICE candidates (buffered before setRemoteDescription)   |
| Server -> Peer  | `peer-disconnected` | `{"type": "peer-disconnected"}`                                 | Notifies remaining peer when connection drops; room destroyed   |
| Server -> Client| `error`             | `{"type": "error", "message": "Room not found" | "Room is full"}`| Signals signaling error                                        |
